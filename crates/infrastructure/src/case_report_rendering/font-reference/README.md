# Pinned font rendering references

These ASCII vectors capture the unchanged bundled Noto Sans Regular and Bold
fonts before replacing rustybuzz 0.20.1 and ttf-parser 0.25.1 with the maintained
engine selected in `docs/adr/0060-durable-authorized-case-reports.md`.
They are fixed expected results, not snapshots regenerated by the replacement.

Each file records unscaled font descriptor metrics, followed by five inputs:
empty text, kerning, Spanish NFC/NFD and combining accents, ligatures, and a
paragraph longer than 4096 bytes. Text and wrapped lines use hexadecimal UTF-8.
Each glyph tuple contains ID, cluster, horizontal and vertical advances,
horizontal and vertical offsets, and nominal horizontal width. Wrapped lines
use font size 10 and width 440; both fonts use Latin/LTR/default features and
monotone grapheme clusters. Tests also verify rendered source spans and one
cached plan per font independently of these fixed vectors.

The capture test ran against the original implementation on 2026-10-02 and
passed once. Its generator and retired libraries are not test dependencies.
The reference SHA-256 digests are:

- Regular: `f36839276f5654c89923cac7bdfa1bb5d7dfced9f8e016a68ffd087b033cc48b`
- Bold: `ef4bce2be721281a00ab691762897ea56df1cd3d6fb6dce8b713d777ac1b9069`

Font admission validates the original font-file hashes before parsing. Updating
font assets, these references, or shaping policy requires a separately reviewed
rendering change; a mismatch is not permission to regenerate expected output.
